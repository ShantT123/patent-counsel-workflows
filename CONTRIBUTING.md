# Contributing

Help make the workflow more useful and more candid about its limits.

## Good first contributions

- A synthetic disclosure that exposes a missed technical question.
- A reproducible example of an unsupported assertion or lost source reference.
- An improved question sequence with a short explanation of its practical value.
- An adapter or installation guide tested in a named assistant and version.
- An evaluation run with inputs, outputs, model/date/settings, and human scores.

## Suggested process

1. Describe the user problem and current behavior in an issue or pull request.
2. Propose a focused change and include a synthetic example when relevant.
3. Run `python3 scripts/check_package.py`.
4. For instruction changes, run relevant challenge cases and report the actual results. Do not describe unexecuted cases as passing.

Contribute only material you have the right to publish. Do not submit client files, unpublished inventions, privileged communications, personal information, or confidential employer materials. Use fictional cases where practical. Removing names alone does not necessarily make a matter safe to publish.

Treat proposed legal rules as jurisdiction- and date-sensitive. Cite primary authority and distinguish requirements from recommendations. Do not turn business scoring into a legal conclusion.

Please discuss substantial integrations first. The core skill should remain usable without paid services or proprietary databases.

Report a confidential concern privately to the maintainer if a private channel is available on their GitHub profile. Do not post sensitive details in a public issue. This project has no dedicated private reporting channel at this release.
